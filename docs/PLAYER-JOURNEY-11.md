# 第十一轮：AI 模拟玩家与调查体验

基线 `272335a25a17c482809bbd7ea78557e25d3db09b` / v0.10.0-dev；本轮 v0.11.0-dev。

## 试玩方法和实际经过

使用官方 Godot 4.7.2，在 X11 / OpenGL Compatibility 软件渲染中实例化真实入口场景。自动玩家通过 WASD 持续行走、鼠标运动事件转视角、E 调查、J 笔记和实际 GUI 的 Tab/Enter 选择进行游戏；没有瞬移、直接发放证据或直接调用取证/推理处理函数。

路线：初次抵达 → 镇口寻人启事 → 小卖部账本、两轮问话、日历 → 广播站日志、四段录音、两轮问话、停播通知 → 首次回街异象 → 公用电话 → 祠堂残页和牌位 → 笔记 → 错误推理 → 正确结论。

基线完成 **12 个画面阶段、12 条线索，步行 156.5 米**。本轮路线增加可选账本互证（先错后对）、H 提示开关、Esc 菜单、取消重开和确认重开，完成 **16 个画面阶段、13 条线索**。

`--fixed-fps 60` 使输入和物理步长可复现；界面选择经过绘制与布局后执行，移动期间暂停重复绘制以缩短自动验收时间。执行用时不能代表真人阅读和通关时长。音频使用 Dummy 驱动，检查的是监听阶段和转录内容，不能据此评价音质、响度或真人配音。

## 发现、影响与修正

| 试玩发现 | 玩家受到的影响 | 本轮改动 |
| --- | --- | --- |
| 笔记累计 12 条长记录后，推理入口在正文末尾 | 需要长距离翻页才能进行核心玩法 | 默认时间线页，推理入口置顶，原文进入单独的证据摘录 |
| 错误推理反馈只有“继续”，随后关闭界面 | 需要重开 J 笔记、再进推理 | 反馈留在推理页面，可直接修改答案 |
| 账本和吴婶证词各自收录，支线没有操作性收束 | 询问之后缺少整理证据的回报 | 新增姓名与身份互证，错误反馈、正确归档及尾声补充 |
| 结尾在祠堂外触发，却写广播站现场断电 | 叙述与玩家眼前地点脱节 | 按街道、小卖部、广播站、祠堂分别设置结尾的声音来源 |
| 陈站长描述为坐姿，吴婶描述为柜台后，实际模型站在旁边 | 人物叙述与场景脱节 | 改为对应站姿和柜台边，去除不存在的持物动作 |
| 墙上通知标 7 月 18 日，问话称其为当夜纸条 | 无意产生的日期矛盾干扰真正的推理 | 明确区分 17 日手写提醒与 18 日停播通知 |
| Esc 只释放鼠标，没有可见菜单 | 操作说明、退出和重开不易发现 | 调查菜单：继续、笔记、操作与提示、重新开始、退出 |
| 初见目标只写建筑名 | 陌生街道中缺少近处物件与左右方位线索 | 按区域细化目标；H 自选方向/距离提示，默认不常驻 |
| 从实际步行接近角度观看寻人告示，文字随镜头转进纸板 | 告示的标题与日期被局部遮住 | 告示文字固定在纸面；连续试玩同一接近角度截图复核 |
| 已结案存档缺少正常重开入口 | 想重新体验时需要外部处理存档 | 游戏内确认重开，备份成功后才清除当前进度；取消不修改记录 |
| 尾声写“第一案原型完成”并直接称模仿者已经诞生 | 开发说明打断氛围，结论超出证据 | 只确认录音与播报的先后，保留身份悬念，产品状态留在项目文档 |

## 存档和玩法约束

- 四条必要证据仍为 `poster`、`ledger`、`log`、`tape`。
- 可选 `ledger_crosscheck` 需要账本与吴婶证词共同解锁，不代替任何主线证据，不强制完成。
- 旧存档字段和文件名保持兼容；新记录沿用现有证据 ID 保存机制。
- 玩家确认重新开始时，先备份现有记录。备份失败会保留当前调查并提示重试。
- 时间线只显示已发现记录的具体时间；不会先替玩家填入未找到的 21:47 或 22:16。

## 验证与工件

```sh
godot --headless --editor --path . --import --quit
godot --headless --path . --script res://tests/smoke.gd
godot --headless --path . --script res://tests/case01.gd
godot --headless --path . --script res://tests/exploration.gd
godot --headless --path . --script res://tests/player_ux.gd
# 需要真实 X11 显示；CI 用 Xvfb。
godot --path . --fixed-fps 60 --rendering-method gl_compatibility --audio-driver Dummy --resolution 1280x720 --script res://tests/player_journey.gd
```

- `player_ux.gd` 验证互证门槛、错误/正确结果、持久化、笔记入口顺序、原地重试、场景对应的尾声、重开备份/取消和提示菜单。
- `player_journey.gd` 验证完整的输入驱动路径，生成 16 张原始引擎 PNG 和 `journey.json`。正式玩家存档不参与试玩。
- 原有 13 张定点实渲染图继续运行，包含 800×600 笔记。
- Actions 增加 `Game2-Player-Journey` 工件，保留逐阶段位置、证据、目标文本和画面。Windows x64 包由相同提交自动导出。
