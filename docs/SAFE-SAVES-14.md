# v0.14.0-dev · 安心存档

## 问题与修复

此前重开复制旧档后立即清空内存、换场景，随后直接打开主档写入。目录只读、文件被占用或写盘失败时，界面仍会显示重开成功；普通保存失败也没有反馈。

新 `SaveStore` 将暂存写入、flush、回读字节及结构校验、有效旧档备份和提交收在一个返回成功与否的流程中。Windows 使用同目录重命名与回滚，不依赖覆盖现有文件的重命名语义。主档和备份替换均保留中断恢复记录。加载只考虑主档、回滚、有效备份及备份回滚，不读取未提交 `.pending`。损坏 JSON 使用可检查解析器，不把预期恢复过程写成引擎错误。

重开先保存本次内存中的全部线索，再提交干净新档；两步均成功后才清空内存、换场景和报告成功。失败保留调查进度、位置与可操作的模态菜单，菜单提供重试保存。普通保存失败显示提示，恢复备份同样显示提示。

## 兼容与边界

保持 `user://case01-save.json`、`found` / `finished` 结构、已知证据 ID 过滤及四项证据完成门槛。已完成主线和可选学校互证不变。当前开发版不增加玩法或修改美术资源。

这是经过回读校验、带回滚的文件提交方案；不承诺断电下的文件系统事务或多进程并发写入。`.previous` 是最近有效版本，后续正常存档可以轮换它，并非永久历史档案。主档与全部备份同时损坏时无法还原调查，保留文件并提示没有有效记录。

## 验证

本地 Godot 4.7.2：原有 smoke、case01、exploration、player_ux、free_roam（100 组）、school 通过。新增 persistence 42 项检查覆盖原始字节备份、两档损坏、结构损坏、旧 ID 过滤、中断提交、不读取暂存、真实文件/目录冲突、提交与回滚故障注入、重开失败、菜单按钮重试、未保存线索和实际场景恢复提示。

首个 Windows 候选的编辑器文件系统 42 项通过，但正式 EXE 忽略 `--script`，启动常规游戏后超时。改为固定、显式的 `--qa-persistence` 入口，在相同导出包中运行同一 Node 检查器；该模式只使用独立 `user://qa` 路径，不改正常调查存档。参见 [官方命令行选项可用性](https://docs.godotengine.org/en/latest/tutorials/editor/command_line_tutorial.html)。

CI 保留全部原有 Linux 逻辑、Windows 导出、真实渲染和连续输入试玩检查；新增 Windows 编辑器与导出 Game2.exe 执行同一 persistence 回归，并记录被测 EXE / PCK SHA256。具体候选及主线结果以 Actions 记录为准，不能把源码检查当作 Windows 真人试玩。
